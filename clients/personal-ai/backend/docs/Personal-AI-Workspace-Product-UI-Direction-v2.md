## 一、产品定位

### 1.1 这个产品是什么

**一个属于 Siyi 的个人 AI 工作空间。**

不是工具集合，不是后台管理系统，不是 SaaS Dashboard。

它是一个「思考和工作的地方」——知识在这里沉淀，经历在这里复盘，能力在这里复用，AI 在这里辅助。

### 1.2 这个产品不是什么

| 不是 | 为什么 |
|------|--------|
| AI 后台管理系统 | 没有多用户、权限、租户等管理概念 |
| SaaS Dashboard | 不需要大量统计卡片、数据图表、KPI 指标 |
| 工具集合 | 功能之间应该有关系，不是平级堆砌 |
| 纯阅读器 | 有交互、有创作、有 AI 辅助 |
| 纯笔记应用 | 核心是「AI 工作空间」，笔记只是知识的一种形态 |

### 1.3 核心工作空间

只有四个，不多不少：

| 工作空间 | 核心问题 | 定位 |
|----------|----------|------|
| **总览** | 我最近在做什么？ | 工作空间的入口和聚合层 |
| **知识** | 我知道了什么？ | 个人知识库，搜索和浏览 |
| **复盘** | 我从经历中学到了什么？ | 反思、洞察、行动跟进 |
| **提示词** | 我有哪些可复用的 AI 能力？ | AI 能力的管理和复用 |

### 1.4 系统功能

| 功能 | 核心问题 | 定位 |
|------|----------|------|
| **网站** | 我的对外 AI 产品发生了什么？ | 运维类，放 SYSTEM 组 |
| **设置** | 这个系统如何运行？ | 系统配置，放 SYSTEM 组 |

### 1.5 Personal AI 的定位

**Personal AI 不是一级导航，不是独立页面。**

Personal AI 是贯穿整个 Workspace 的「智能层」：
- 在任何页面都可以调用
- 感知用户当前上下文（在看什么、搜什么、做什么）
- 提供与当前场景相关的 AI 能力
- 入口在 Header，不是侧边栏

## 二、信息架构

### 2.1 一级导航

```
┌─────────────────────┐
│  Siyi Workspace     │
│                     │
│  WORKSPACE          │
│  □ 总览              │
│  □ 知识              │
│  □ 复盘              │
│  □ 提示词            │
│                     │
│  SYSTEM             │
│  □ 网站              │
│  □ 设置              │
│                     │
│  ● 索引已同步        │
│  328 篇笔记          │
└─────────────────────┘
```

**导航原则**:
- WORKSPACE 组：4 个核心工作空间，用户日常使用
- SYSTEM 组：2 个系统功能，低频使用，视觉上弱化
- 底部：轻量的 Obsidian/Index 状态，不占导航位置
- 总共 6 个导航项，比当前 7 个（含 2 个禁用）更精简
- 没有「信息雷达」「英语学习」等未实现功能的占位

### 2.2 二级导航（页面内）

| 页面 | 二级导航形式 | 内容 |
|------|-------------|------|
| 总览 | 无 | 单页聚合，不需要 Tab |
| 知识 | 无 | 搜索即首页，搜索模式作为搜索框附属控件 |
| 复盘 | Tabs（4个） | 复盘 / 洞察 / 行动 / 总览 |
| 提示词 | 无 | 列表即首页，分类作为筛选条件 |
| 网站 | 无 | 单页内容 |
| 设置 | 内部分区（Divider 分隔） | 索引配置 / 系统运维 / 关于 |

**关键决策：复盘页的 4 个 Tab**

「复盘 / 洞察 / 行动 / 总览」继续作为 AI 复盘库的内部 Tab，不拆成一级导航。理由：
1. 四个概念都围绕「复盘」这一核心活动展开
2. 用户在「写复盘 → 看洞察 → 跟进行动 → 看统计」的流程中需要频繁切换
3. Tab 切换比页面跳转成本低，符合「少入口、多关系」
4. 拆成一级导航会增加认知负担，且「洞察」「行动」「总览」单独作为一级入口概念太弱

**关系说明**:
- **总览 ← 知识 + 复盘**：总览聚合最近知识、最近复盘、当前行动
- **复盘 ↔ 知识**：复盘可以引用知识，知识可以显示「被哪些复盘引用」
- **复盘 ↔ 提示词**：复盘生成可以使用 Prompt，复盘可以提炼为 Prompt
- **知识 ↔ 提示词**：Prompt 可以引用知识作为上下文
- **Personal AI ← 所有页面**：感知当前上下文，提供场景化 AI 能力
- **网站 ← 复盘**：标记为公开的复盘可以展示在对外网站
- **设置 → 所有页面**：系统配置影响所有页面

### 2.4 每个页面的核心任务

| 页面 | 核心任务 | 用户进入页面后应该做什么 |
|------|----------|------------------------|
| 总览 | 了解最近动态，快速进入工作 | 看待办行动 → 点进去做；看最近知识/复盘 → 点进去继续 |
| 知识 | 找到需要的知识，阅读和理解 | 搜索 → 看结果 → 点开详情阅读 |
| 复盘 | 记录和反思经历，跟进行动 | 看复盘列表 → 点开详情/写新复盘 → 看洞察/跟进行动 |
| 提示词 | 管理和复用 AI 能力 | 找提示词 → 看详情 → 使用/编辑/生成新提示词 |
| 网站 | 了解对外产品状态 | 看访客/会话数据，管理内容 |
| 设置 | 配置系统运行方式 | 配置索引源，管理备份，查看系统信息 |

### 2.5 每个页面应该显示什么

#### 总览
- ✅ 当前行动（待办，最多 5 条）
- ✅ 最近知识（最近访问/搜索，5-8 条）
- ✅ 最近复盘（最近创建/更新，5-8 条）
- ✅ 快速入口（新建复盘、搜索知识、管理提示词）
- ✅ 非侵入式系统状态（索引状态、文件数，底部轻量显示）
- ❌ 统计卡片（文件数、字数、标签数）
- ❌ 图表（热力图、趋势图）
- ❌ 搜索框（用 Header 全局搜索）
- ❌ 欢迎语大标题（可以有轻量问候，但不占视觉中心）

#### 知识
- ✅ 大搜索框（页面视觉中心）
- ✅ 搜索模式切换（关键词/语义/混合，搜索框附属）
- ✅ 搜索历史/建议（无输入时显示）
- ✅ 搜索结果列表（标题、类型、来源、摘要、时间）
- ✅ 知识详情（右侧 Drawer）
- ✅ 最近访问（无搜索时默认显示）
- ❌ 分类导航（分类作为 Badge 和筛选，不是独立导航）
- ❌ 标签云（标签在详情内显示）
- ❌ 统计数字（不显示文件数、字数）
- ❌ 知识图谱（如果没有真实数据）

#### 复盘
- ✅ 4 个 Tab（复盘/洞察/行动/总览）
- ✅ 「复盘」Tab：搜索框、筛选、复盘列表、新建按钮
- ✅ 复盘详情（Drawer 或 Modal，阅读宽度更大）
- ✅ 「洞察」Tab：AI 生成的洞察列表，关联复盘
- ✅ 「行动」Tab：行动项列表，完成状态，新建行动
- ✅ 「总览」Tab：轻量统计（文字+数字）、热力图、趋势
- ❌ 复盘列表页显示统计卡片（统计移到「总览」Tab）
- ❌ 多种视图切换（只保留列表视图）
- ❌ 复盘详情内显示所有功能（详情聚焦内容，行动移到「行动」Tab）

#### 提示词
- ✅ 搜索框、分类筛选、新建按钮、AI 生成按钮
- ✅ 提示词列表（标题、分类、收藏、预览、最后使用时间）
- ✅ 提示词详情（右侧 Drawer，可编辑）
- ✅ 收藏置顶
- ❌ 分类导航（分类作为筛选，不是独立导航）
- ❌ 使用次数统计（不显示，或详情内轻量显示）
- ❌ 多种视图切换（只保留列表视图）
- ❌ 导入导出（放设置或更多操作菜单）

### 2.6 哪些内容应该隐藏/降级/删除

#### 降级为筛选/属性
| 当前定位 | 建议定位 | 理由 |
|----------|----------|------|
| 知识类型/分类 | 搜索结果的 Badge + 筛选条件 | 不是独立功能，是知识的属性 |
| 复盘标签 | 复盘列表的筛选条件 | 不是独立页面，是复盘的属性 |
| 提示词分类 | 提示词列表的筛选条件 | 不是独立导航，是提示词的属性 |
| 行动项状态 | 行动列表的筛选条件 | 不是独立页面，是行动的属性 |
| 搜索模式（关键词/语义/混合） | 搜索框附属控件 | 不是独立功能，是搜索的参数 |
| 索引状态 | Sidebar 底部轻量显示 | 不是独立功能，是系统状态 |

#### 从页面中删除但暂时保留代码
| 功能 | 原因 | 处理方式 |
|------|------|----------|
| 侧边栏拖拽排序 | 用户几乎不会用，增加 150+ 行代码 | 移除 UI，保留代码备份 |
| 侧边栏可拖拽调整宽度 | 固定宽度即可，resizer 增加复杂度 | 移除 UI，保留代码备份 |
| 设置页的统计卡片 | 统计应该在复盘「总览」Tab，设置页不需要 | 移除 UI，保留 API |
| 全局 loading 全屏遮罩 | 阻塞用户操作，应该用局部 loading | 移除 UI，保留代码 |
| 信息雷达/英语学习导航项 | 未实现，占位增加认知负担 | 移除导航，保留代码备份 |
| 6 个不存在模块的快捷键 | 按了没反应，用户困惑 | 移除快捷键定义 |
| index.html 引用的 /modules/agent/style.css | 404，无意义 | 移除引用 |

- 设置入口：⚙ 图标按钮（32x32px，圆角 6px）

- 按 Enter → 跳转到知识页，显示搜索结果
- 搜索建议/历史下拉显示
- 搜索框不阻塞当前页面，是浮层形式

### 3.4 Content Area

**背景**: 页面背景色（#F7F6FB 或类似的浅灰紫色）

**宽度策略**: 不强制所有页面 960px，根据页面内容决定

| 页面类型 | 最大宽度 | 理由 |
|----------|----------|------|
| 总览 | 800-960px | 聚合内容，不需要太宽 |
| 知识（搜索框） | 640-720px | 搜索框居中，聚焦感 |
| 知识（搜索结果） | 800-960px | 列表内容，适中宽度 |
| 复盘（列表） | 960-1100px | 列表型页面，可以更宽 |
| 复盘（详情） | 800-960px | 阅读型内容，适中宽度 |
| 提示词（列表） | 800-960px | 列表内容，适中宽度 |
| 提示词（详情） | 640-720px | 编辑型内容，不需要太宽 |
| 设置 | 640-720px | 表单内容，窄宽度更聚焦 |

**边距**:
- 左右边距：32-48px（根据屏幕宽度自适应）
- 上下边距：32-40px
- 页面标题区与内容区间距：24-32px

**不做**:
- ❌ 强制所有页面 960px
- ❌ 内容区使用卡片包裹（内容直接放在 Canvas 上）
- ❌ 内容区使用背景色区分（与页面背景相同）
- ❌ 内容区使用边框或阴影

- 「总览」Tab 为空：「还没有数据。开始写复盘后，这里会显示你的写作统计和趋势。」
- 搜索无结果：「没有找到与「xxx」相关的复盘。试试其他关键词。」

**Loading 状态**:
- 列表加载：骨架屏（3-5 条占位）
- 详情加载：Modal/Drawer 内 spinner
- AI 生成中：显示「AI 正在分析...」+ 进度提示，不阻塞用户操作
- 洞察生成中：显示「AI 正在生成洞察...」+ 预计时间
- 不是全屏 loading

**Detail 展开方式**:
- 复盘详情：Modal 居中（推荐，因为复盘内容较长，需要更大阅读宽度），或右侧 Drawer（宽度 800-960px）
- 洞察详情：展开式（点击洞察后在下方展开关联复盘列表）
- 行动详情：不需要详情，直接在列表中操作（复选框 + 行内编辑）
- Modal/Drawer 打开时，背景列表保持可滚动

**与其他模块的关系**:
- 数据来源：SQLite 数据库（复盘、行动项）、AI Core（洞察生成、复盘分析）
- 与知识的关系：复盘可以引用知识，复盘内容可以被知识检索索引
- 与提示词的关系：复盘生成可以使用 Prompt，复盘可以提炼为 Prompt
- Personal AI：可以基于复盘内容提供分析建议、生成行动项、提炼洞察
- 总览页：最近复盘和当前行动来自这里
- 网站（Meet Siyi）：标记为公开的复盘可以展示在对外网站
- 复盘是四个核心页面中功能最复杂的，需要最仔细的设计

**什么应该占据视觉中心**:
- 「复盘」Tab：复盘列表（用户的核心内容）
- 「行动」Tab：待办行动（用户接下来要做什么）
- 「洞察」Tab：AI 洞察（用户从中学到了什么）
- 「总览」Tab：统计数据（用户的整体情况）
- 不是新建按钮、不是筛选、不是统计卡片、不是多种视图切换

## 六、Personal AI（智能层）

### 6.1 定位

**Personal AI 不是一级导航，不是独立页面。**

Personal AI 是贯穿整个 Workspace 的「智能层」：
- 在任何页面都可以调用
- 感知用户当前上下文（在看什么、搜什么、做什么）
- 提供与当前场景相关的 AI 能力
- 是工作空间的「智能助手」，不是另一个功能模块

### 6.2 入口

| 入口 | 位置 | 触发方式 |
|------|------|----------|
| Header 按钮 | Header 右侧，✦ 图标 | 点击打开面板 |
| 快捷键 | 全局 | Cmd/Ctrl + J（或其他快捷键） |
| 页面内按钮 | 各页面的「AI 生成」「使用」等按钮 | 点击触发特定功能，自动打开面板并填入上下文 |
| 选中文字 | 任何页面的可选中文字 | 右键菜单或浮动工具栏（可选） |

**不做**:
- ❌ 右下角悬浮按钮（遮挡内容，且与 Header 入口重复）
- ❌ 侧边栏导航项（不是独立功能）
- ❌ 独立页面（AI 是辅助层，不是主功能）

### 6.3 面板

**形式**: 右侧滑出面板（Drawer），或右下角悬浮面板（保留现有形式，但入口改为 Header）

**尺寸**:
- 宽度：360-420px
- 高度：100%（Drawer 形式）或 560-640px（悬浮面板形式）

**结构**:
```
┌──────────────────────┐
│  ✦ Siyi AI      [✕]  │  ← 标题 + 关闭
│                      │
│  当前：知识页          │  ← 上下文感知
│  正在查看：知识图谱设计  │
│  搜索：设计令牌        │
│                      │
│  ┌──────────────────┐ │
│  │                  │ │
│  │  对话内容区       │ │
│  │                  │ │
│  │  AI：基于你当前  │ │
│  │  查看的知识，我... │ │
│  │                  │ │
│  │  你：帮我总结...  │ │
│  │                  │ │
│  └──────────────────┘ │
│                      │
│  快捷操作：            │
│  [总结当前] [生成复盘] [优化提示词] │
│                      │
│  ┌──────────────────┐ │
│  │ 输入消息...    [发送]│ │
│  └──────────────────┘ │
└──────────────────────┘
```

**上下文感知**（面板顶部显示当前上下文）:
- 当前模块：总览 / 知识 / 复盘 / 提示词 / 网站 / 设置
- 当前查看的内容：知识详情标题 / 复盘详情标题 / 提示词详情标题
- 当前搜索关键词：如果有
- 当前筛选条件：如果有
- 上下文可以被用户清除（「清除上下文」按钮）

**快捷操作**（根据当前页面动态变化）:
| 当前页面 | 快捷操作 |
|----------|----------|
| 总览 | 总结最近动态、生成周报、整理待办优先级 |
| 知识 | 总结当前知识、生成知识卡片、关联知识推荐 |
| 复盘 | 生成复盘草稿、分析当前复盘、创建行动项、提炼洞察 |
| 提示词 | 生成提示词、优化当前提示词、测试提示词 |
| 网站 | 总结访客数据、生成运营建议 |
| 设置 | 解释配置项、排查问题 |

**对话功能**:
- 支持多轮对话
- AI 回复可以包含代码块、列表、引用等格式
- 支持 Markdown 渲染
- 对话历史保存在当前会话中，面板关闭后保留（可选，或用户手动清除）
- 对话历史不跨设备同步（本地存储）

### 6.4 与各页面的集成

| 页面 | Personal AI 能力 |
|------|-----------------|
| 总览 | 基于最近活动提供建议和总结；生成周报；整理待办优先级 |
| 知识 | 回答关于当前搜索结果的问题；基于查看的知识生成摘要；推荐相关知识 |
| 复盘 | 生成复盘草稿（基于用户输入的经历描述）；分析复盘内容；创建行动项；提炼洞察；生成复盘标题 |
| 提示词 | 生成提示词（基于需求描述）；优化提示词；测试提示词效果；从复盘中提炼提示词 |
| 网站 | 总结访客数据；生成运营建议；回答关于会话记录的问题 |
| 设置 | 解释配置项；排查索引问题；提供配置建议 |

**集成方式**:
- 页面内的「AI 生成」「使用」等按钮 → 打开 Personal AI 面板，自动填入上下文和初始指令
- 面板打开时 → 自动读取当前页面上下文（模块、查看内容、搜索关键词）
- AI 回复中的操作按钮（如「创建行动项」「保存为提示词」）→ 直接执行对应操作，不需要用户手动复制

### 6.5 不做

- ❌ 独立的 Personal AI 页面
- ❌ 侧边栏导航项
- ❌ 右下角悬浮按钮（或保留但入口主要在 Header）
- ❌ 复杂的 Agent 工作流（第一阶段只做对话 + 上下文感知 + 快捷操作）
- ❌ 跨设备同步对话历史
- ❌ 语音输入/输出
- ❌ 插件市场

## 七、Design Principles（视觉语言）

### 7.1 视觉关键词

**Quiet · Personal · Soft · Editorial · Intelligent**

| 关键词 | 含义 | 设计体现 |
|--------|------|----------|
| **Quiet（安静）** | 不抢眼，不喧宾夺主 | 低饱和色彩、克制的装饰、内容优先 |
| **Personal（个人）** | 有温度，不是冷冰冰的工具 | 柔和的色彩、舒适的间距、个人空间感 |
| **Soft（柔和）** | 不尖锐，不生硬 | 小圆角、柔和的阴影、低对比度边框 |
| **Editorial（编辑感）** | 像阅读一本杂志或一本书 | 清晰的排版层级、舒适的行高、内容的节奏感 |
| **Intelligent（智能）** | AI 能力自然融入 | 克制的 AI 入口、上下文感知、不突兀的智能提示 |

### 7.2 避免

| 避免 | 为什么 |
|------|--------|
| **SaaS Dashboard** | 这是个人工作空间，不是企业管理后台 |
| **大量数据卡片** | 统计不是核心，内容才是；卡片过多增加视觉噪音 |
| **过度玻璃拟态** | 玻璃拟态容易显得花哨，且可读性差；用纯色 Surface 更清晰 |
| **霓虹科技感** | 与「安静、个人」的定位不符 |
| **大面积渐变** | 渐变容易显得花哨，且阅读体验差；用纯色或极轻微的渐变 |
| **emoji 作为 UI icon** | emoji 在不同平台渲染不一致，且不够专业；用线性 SVG 图标 |
| **过度圆角** | 大圆角（>12px）显得幼稚；用 6-10px 的小圆角更成熟 |
| **大量阴影** | 阴影容易显得厚重；几乎不用阴影，用边框和背景色区分层级 |
| **大量边框** | 边框过多增加视觉噪音；用间距和 Divider 分隔，不用卡片边框 |

### 7.3 色彩系统

**核心原则**: 紫色是 Accent，不是主视觉背景。整体是安静的浅灰紫色调。

| 角色 | 色值（参考） | 用途 |
|------|-------------|------|
| **Background** | `#F7F6FB` 或 `#F5F4F9` | 页面背景，非常浅的灰紫色，不是纯白，也不是明显的紫色 |
| **Surface** | `#FFFFFF` 或 `#FAF9FC` | 输入框、Modal、Drawer、选中项背景，比背景稍白或稍暗 |
| **Surface-hover** | `rgba(45,42,53,0.02)` | 列表项 Hover 背景，极轻微的暗色 |
| **Text-primary** | `#2D2A35` 或 `#33303D` | 标题、重要文字，深灰紫色，不是纯黑 |
| **Text-secondary** | `#6B6875` | 正文、摘要，中灰色 |
| **Text-muted** | `#9A97A3` | 辅助文字、元信息，浅灰色 |
| **Text-disabled** | `#C4C0D0` | 禁用文字 |
| **Accent** | `#7A5ECD` 或 `#6C5CE7` | 链接、按钮、选中状态、重要操作，紫色，饱和度适中 |
| **Accent-hover** | `#8B6FE0` | Accent 悬停状态 |
| **Accent-pressed** | `#6A4EC0` | Accent 按下状态 |
| **Accent-tint** | `rgba(122,94,205,0.06)` | 选中项背景、标签背景，非常浅的紫色 |
| **Accent-ring** | `rgba(122,94,205,0.25)` | 焦点环 |
| **Border** | `rgba(45,42,53,0.08)` | 分隔线、输入框边框，非常浅的灰紫色 |
| **Border-strong** | `rgba(45,42,53,0.12)` | 输入框边框、按钮边框，稍深一点 |
| **Divider** | `rgba(45,42,53,0.06)` | 列表项分隔、区域分隔，极浅 |
| **Success** | `#5B8C6E` | 成功状态，柔和的绿色，不是高饱和的绿 |
| **Warning** | `#B8865A` | 警告状态，柔和的橙色 |
| **Danger** | `#B06068` | 危险状态，柔和的红色 |
| **Info** | `#5A8AA8` | 信息状态，柔和的蓝色 |

**色彩使用规则**:
- 背景只用 Background 色，不用渐变，不用图案
- Surface 用于需要从背景中突出的元素（输入框、Modal、Drawer）
- Accent 只用于：链接、主按钮、选中状态、重要操作、焦点环
- Accent 不用于：背景、大面积填充、装饰
- 文字颜色只用 3-4 级（primary/secondary/muted/disabled），不用更多层级
- 状态色（success/warning/danger/info）只用于状态指示，不用于装饰
- 不用纯黑（#000000），不用纯白（#FFFFFF）作为背景（Surface 可以用 #FFFFFF）

### 7.4 排版系统

**字体**:
- 主字体：系统无衬线字体栈（`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Microsoft YaHei", sans-serif`）
- 等宽字体：`"SF Mono", "JetBrains Mono", Consolas, monospace`（用于代码、提示词内容）
- 不用衬线字体（除非特定的 Editorial 设计需求）
- 不用外部字体（保持加载速度和系统一致性）

**字号层级**（最多 6 级，不用更多）:

| 层级 | 字号 | 字重 | 行高 | 用途 |
|------|------|------|------|------|
| Display | 24px | 600 | 1.3 | 页面大标题（很少用） |
| Title | 20px | 600 | 1.3 | 页面标题、Modal/Drawer 标题 |
| Heading | 16-18px | 600 | 1.4 | 区块标题、分区标题 |
| Body | 14px | 400 | 1.6-1.7 | 正文、列表内容、摘要 |
| Caption | 12-13px | 400 | 1.5 | 辅助文字、元信息、标签 |
| Micro | 11px | 500 | 1.4 | 分组标签、Badge 文字、快捷键提示 |

**字重**:
- 只用 3 级：400（常规）、500（中等）、600（半粗）
- 不用 700+（太粗，与「安静」定位不符）
- 不用 300（太细，可读性差）

**排版规则**:
- 页面标题与描述之间间距 4-8px
- 标题与内容之间间距 16-24px
- 段落之间间距 12-16px
- 列表项之间间距 16-24px（或用 Divider）
- 行高：正文 1.6-1.7，标题 1.3-1.4，辅助文字 1.5
- 不用过大的标题（页面标题最多 20-24px）
- 不用过多字重变化（同一段落内字重变化不超过 2 级）
- 文字颜色与背景对比度符合 WCAG AA 标准（正文 ≥ 4.5:1，大文字 ≥ 3:1）

### 7.5 间距系统

**基础单位**: 4px

**间距标度**（只用这些值，不用中间值）:

| 令牌 | 值 | 用途 |
|------|-----|------|
| xs | 4px | 极小间距，图标与文字之间 |
| sm | 8px | 小间距，按钮内元素之间 |
| md | 12px | 中等间距，表单元素之间 |
| lg | 16px | 大间距，列表项之间、元素内边距 |
| xl | 24px | 超大间距，区块之间、页面内容区 |
| 2xl | 32px | 页面上下边距、大区块之间 |
| 3xl | 40-48px | 页面左右边距、页面顶部边距 |

**间距规则**:
- 页面左右边距：32-48px（根据屏幕宽度自适应，最小 24px）
- 页面上下边距：32-40px
- 页面标题区与内容区间距：24-32px
- 区块之间间距：24-32px（或用 Divider + 24px 间距）
- 列表项之间间距：16-24px（或用 Divider）
- 元素内部 padding：12-16px（输入框、按钮）
- 不用过大的间距（保持信息密度合理，一屏能看到足够内容）
- 不用过小的间距（元素之间至少 4px，可点击元素至少 32x32px）
- 垂直间距大于水平间距（符合阅读习惯）

### 7.6 圆角系统

| 令牌 | 值 | 用途 |
|------|-----|------|
| sm | 4-6px | Badge、标签、小按钮 |
| md | 6-8px | 按钮、输入框、列表项 Hover |
| lg | 10-12px | Card、Modal、Drawer、大按钮 |
| pill | 999px | 圆形按钮、头像、胶囊标签 |

**圆角规则**:
- 按钮/输入框：6-8px（小圆角，不是大圆角）
- 卡片/Modal/Drawer：10-12px
- 标签/Badge：4-6px 或 pill
- 不用 16px 以上的大圆角（显得幼稚）
- 不用 0px 直角（显得生硬）
- 同一组件的圆角统一，不用混合圆角
- 圆形元素（头像、圆形按钮）用 50% 或 pill

### 7.7 阴影系统

**核心原则**: 几乎不用阴影。用边框和背景色区分层级。

| 令牌 | 值 | 用途 |
|------|-----|------|
| none | 无 | 按钮、卡片、列表项（默认无阴影） |
| sm | `0 1px 3px rgba(45,42,53,0.04)` | 极轻微阴影，用于 Modal/Drawer（可选） |
| md | `0 4px 12px rgba(45,42,53,0.06)` | 中等阴影，用于 Modal/Drawer、下拉菜单 |
| lg | `0 8px 24px rgba(45,42,53,0.08)` | 大阴影，用于 Modal（很少用） |

**阴影规则**:
- 按钮：不用阴影
- 卡片：不用阴影（用边框或背景色区分）
- 列表项：不用阴影
- Modal/Drawer：可以用 sm 或 md 阴影（因为需要从背景中突出）
- 下拉菜单/Popover：用 sm 或 md 阴影
- 不用浮动阴影、不用新拟态阴影、不用彩色阴影
- 阴影颜色用灰紫色（rgba(45,42,53,X)），不用纯黑（rgba(0,0,0,X)）
- 阴影透明度很低（0.04-0.08），几乎不可见，只是增加一点层次感

### 7.8 边框系统

| 令牌 | 值 | 用途 |
|------|-----|------|
| Divider | `1px solid rgba(45,42,53,0.06)` | 列表项分隔、区域分隔 |
| Border | `1px solid rgba(45,42,53,0.08)` | 卡片边框、输入框边框（默认） |
| Border-strong | `1px solid rgba(45,42,53,0.12)` | 输入框边框 Hover、按钮边框 |
| Border-accent | `1px solid #7A5ECD` | 选中状态、焦点状态 |

**边框规则**:
- 分隔线用 Divider（极浅），不用 Border
- 输入框/按钮边框用 Border 或 Border-strong
- 卡片默认无边框（用背景色或间距区分），需要时用 Border
- 不用粗边框（>1px），不用虚线边框（除了特定的拖拽提示）
- 不用彩色边框（除了选中/焦点状态用 Accent 色）
- 列表项之间用 Divider 或间距，不用每个列表项都有边框
- 边框颜色与背景对比度低（几乎不可见，只是增加一点边界感）

### 7.9 图标系统

**图标风格**:
- 线性 SVG 图标，1.5px 线条
- 圆角端点和连接（round cap/join）
- 24x24px 视口，实际显示 14-16px
- 颜色：继承文字颜色（currentColor），或 Text-secondary 色
- 不用填充图标、不用彩色图标（除了状态指示）
- 不用 emoji 作为 UI 图标

**图标尺寸**:
| 尺寸 | 用途 |
|------|------|
| 12px | 极小图标，Badge 内 |
| 14px | 小图标，按钮内、列表项内 |
| 16px | 默认图标，Header 按钮、操作按钮 |
| 20px | 大图标，空状态图标（很少用） |

**图标使用规则**:
- 图标 + 文字组合：图标在左，文字在右，间距 6-8px
- 纯图标按钮：32x32px 点击区域，图标 16px
- 图标颜色与文字颜色一致（currentColor）
- 状态图标（成功/警告/危险）可以用对应颜色
- 不用图标装饰（图标只用于功能指示，不用纯装饰）
- 图标集保持一致（同一套线性图标，不用混合风格）

### 7.10 动效系统

**核心原则**: 克制、快速、自然。动效是为了反馈，不是为了炫技。

| 动效 | 时长 | 缓动 | 用途 |
|------|------|------|------|
| Fast | 120ms | ease-out | 按钮 Hover、颜色变化、小元素显示/隐藏 |
| Base | 200ms | ease-out | 页面切换、Modal/Drawer 打开/关闭、Tab 切换 |
| Slow | 300ms | ease-out | 大元素动画、列表重排（很少用） |

**动效规则**:
- 按钮 Hover/Active：120ms，颜色/背景变化
- 列表项 Hover：120ms，背景变化
- Modal/Drawer 打开/关闭：200ms，透明度 + 位移/缩放
- 页面切换：200ms，透明度变化（不用复杂的转场动画）
- Tab 切换：150ms，下划线/背景变化
- 加载状态：spinner 旋转（1s 循环）或骨架屏（不用跳动动画）
- 不用弹性动画（cubic-bezier 带过冲的）
- 不用超过 300ms 的动画（显得慢）
- 不用连续循环的动画（除了 loading spinner）
- 不用视差滚动、不用粒子效果、不用 3D 变换
- 尊重用户的「减少动态效果」系统设置（prefers-reduced-motion）

## 八、Component Principles（组件体系）

### 8.1 组件清单

只定义真正需要统一的基础组件，不创建庞大的前端框架。

| 组件 | 用途 | 必须性 |
|------|------|--------|
| **Button** | 操作按钮 | 必须 |
| **Input** | 文本输入、文本域 | 必须 |
| **Select** | 下拉选择 | 必须 |
| **Tabs** | 页面内 Tab 切换 | 必须（复盘页） |
| **Drawer** | 右侧滑出详情面板 | 必须（知识、提示词） |
| **Modal** | 居中模态框 | 必须（复盘详情、新建） |
| **Badge** | 标签、状态指示 | 必须 |
| **EmptyState** | 空状态 | 必须 |
| **Loading** | 加载状态 | 必须 |
| **Toast** | 轻量通知 | 必须 |

**不做的组件**:
- ❌ Card（不默认成为所有内容的容器，见 8.2）
- ❌ Dropdown（用 Select 或简单的下拉菜单，不做复杂组件）
- ❌ Table（用列表代替，数据量不大）
- ❌ Pagination（用无限滚动或「加载更多」按钮）
- ❌ DatePicker（用 Input + 简单的日期选择，不做复杂组件）
- ❌ Tree（知识结构不用树形视图，用列表和搜索）
- ❌ Chart（总览页用简单图表，不做复杂图表组件库）

### 8.2 Card 使用规则

**Card 不默认成为所有内容的容器。**

#### 什么时候用 Card

| 场景 | 理由 | 示例 |
|------|------|------|
| 需要从背景中突出的独立内容块 | 视觉上需要区分 | Modal 内容、Drawer 内容 |
| 包含多个交互元素的复合组件 | 需要容器组织 | 空状态容器、统计卡片（总览页，少量） |
| 需要边框或阴影的浮层 | 浮层需要从背景中突出 | 下拉菜单、Popover、Tooltip |
| 用户创作内容的展示 | 需要区分用户内容和 UI 框架 | 复盘详情内的引用块、代码块 |

#### 什么时候不用 Card

| 场景 | 替代方案 | 示例 |
|------|----------|------|
| 列表项 | 直接放在 Canvas 上，用 Divider 或间距分隔 | 搜索结果列表、复盘列表、提示词列表 |
| 页面区块 | 用区块标题 + Divider + 间距 | 总览页的「当前行动」「最近知识」 |
| 操作栏 | 直接放在 Canvas 上，用间距分隔 | 搜索框 + 筛选 + 新建按钮 |
| 表单 | 直接放在 Canvas 上，用表单元素间距 | 设置页的表单 |
| 普通文本内容 | 直接放在 Canvas 上 | 页面描述、说明文字 |

#### Card 样式（当需要用时）

- 背景：Surface 色（#FFFFFF 或 #FAF9FC）
- 边框：1px solid Border（rgba(45,42,53,0.08)），或无边框
- 圆角：10-12px
- 阴影：无，或 sm 极轻微阴影
- 内边距：16-24px
- 不用卡片包裹每个列表项
- 不用卡片包裹每个页面区块
- 页面上同时存在的 Card 不超过 3-5 个

### 8.3 内容容器层级

从「最直接」到「最突出」：

1. **Canvas（画布）** — 默认，所有内容直接放在这里
   - 页面背景色，无边框，无阴影
   - 用于：页面标题、描述、列表、操作栏、普通文本

2. **Divider（分隔线）** — 分隔内容区块或列表项
   - 1px 横线，极浅颜色
   - 用于：列表项之间、区块之间
   - 不是容器，只是分隔

3. **Surface（表面）** — 与背景有轻微区分的区域
   - 稍白或稍暗的背景色，无边框，无阴影
   - 用于：输入框背景、选中项背景、Hover 背景
   - 比 Canvas 稍突出，但不明显

4. **Card（卡片）** — 需要从背景中突出的独立内容块
   - 背景 + 边框 + 圆角，可能有极轻微阴影
   - 用于：Modal 内容、Drawer 内容、空状态、少量统计卡片
   - 最突出，但克制使用

**使用原则**:
- 优先用 Canvas（直接放内容）
- 需要分隔时用 Divider
- 需要轻微区分时用 Surface
- 只有真正需要突出时才用 Card
- 不要「为了好看」而用 Card

### 8.4 各页面容器使用判断

| 页面 | 内容 | 容器 | 理由 |
|------|------|------|------|
| 总览 | 当前行动列表 | Canvas + Divider | 列表项，不需要卡片 |
| 总览 | 最近知识/最近复盘 | Canvas + 两列布局 | 列表，不需要卡片 |
| 总览 | 快速入口 | Canvas + 文字链接 | 操作引导，不需要卡片 |
| 总览 | 空状态 | Card（居中） | 空状态需要突出 |
| 知识 | 搜索框 | Surface（输入框背景） | 输入框需要从背景中区分 |
| 知识 | 搜索结果列表 | Canvas + Divider | 列表项，不需要卡片 |
| 知识 | 知识详情 | Drawer（浮层） | 详情需要浮层 |
| 复盘 | 操作栏 | Canvas | 搜索+筛选+按钮，不需要卡片 |
| 复盘 | 复盘列表 | Canvas + Divider | 列表项，不需要卡片 |
| 复盘 | 复盘详情 | Modal 或 Drawer（浮层） | 详情需要浮层 |
| 复盘 | 洞察列表 | Canvas + 展开式 | 列表，不需要卡片 |
| 复盘 | 行动列表 | Canvas + Divider | 列表项，不需要卡片 |
| 复盘 | 总览统计 | Canvas + 文字行（少量可用 Card） | 统计可以用少量卡片，但优先文字行 |
| 提示词 | 操作栏 | Canvas | 搜索+筛选+按钮，不需要卡片 |
| 提示词 | 提示词列表 | Canvas + Divider | 列表项，不需要卡片 |
| 提示词 | 提示词详情 | Drawer（浮层） | 详情需要浮层 |
| 设置 | 表单分区 | Canvas + Divider | 表单，不需要卡片 |
| 设置 | 备份列表 | Canvas + Divider | 列表项，不需要卡片 |

**结论**: 90% 的内容直接放在 Canvas 上，用 Divider 或间距分隔。只有 Modal/Drawer 浮层、空状态、少量统计卡片使用 Card。

### 8.5 组件设计原则

1. **一致性** — 同一种组件在所有页面中外观和行为一致
2. **克制** — 组件数量少而精，不做不必要的组件
3. **可访问性** — 所有组件支持键盘操作、焦点管理、ARIA 标签
4. **状态完整** — 每个组件都有 default/hover/active/focus/disabled 状态
5. **不依赖框架** — 用原生 JS + CSS 实现，不引入 React/Vue
6. **轻量** — 每个组件代码量小，不做过度抽象
7. **可组合** — 组件可以组合使用，但不依赖复杂的组件树
8. **内容优先** — 组件是内容的容器，不是内容本身
